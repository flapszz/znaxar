# СДЭК: что готово и что нужно от партнёра

Интеграция подготовлена и **выключена**, пока на сервере нет ключей. Покупателям и владельцу сайт
работает как раньше: в админке под заявкой написано «Накладную СДЭК можно будет создать здесь позже».

## Что уже есть в коде
- `server/cdek/client.js` — клиент API СДЭК v2: токен (кешируется), повтор при протухании, понятные ошибки.
- `server/routes/cdek.js`:
  - `GET /api/cdek/status` — подключена ли интеграция;
  - `GET /api/cdek/cities?q=` — поиск города; `GET /api/cdek/points?city_code=` — пункты выдачи;
  - `POST /api/cdek/calc` — стоимость и срок доставки по составу корзины (вес считает сервер);
  - `POST /api/cdek/orders/:id/create` — накладная **только по кнопке владельца** после подтверждения заявки;
  - `POST /api/cdek/orders/:id/refresh` — обновить номер и статус;
  - `POST /api/cdek/webhook?token=…` — приём статусов от СДЭК (секрет в адресе).
- В админке у заявки: пункт выдачи (можно вписать вручную), кнопка «Создать накладную СДЭК», статус.
- В базе: `orders.pickup_code`, `city_code`, `cdek_uuid`, `cdek_number`, `cdek_status`, `cdek_error`; `products.weight_g`.
- Проверено на локальной заглушке СДЭК (весь цикл), **с настоящим API не проверялось** — сверить на тестовом контуре.

## Что нужно получить от партнёра
1. `client_id` и `client_secret` для **тестового** контура (`https://api.edu.cdek.ru/v2`) и для **боевого** (`https://api.cdek.ru/v2`).
2. **Город отправления** (код города СДЭК) и **пункт, откуда сдаём посылки** (код склада/ПВЗ СДЭК) или адрес забора курьером.
3. Данные отправителя: название ИП, телефон.
4. Номер договора и подтверждение, что тариф «Посылка склад-склад» (код 136) подходит; иначе — нужный код тарифа.
5. Решение по оплате при получении: наложенный платёж включён в договоре.
6. Для виджета карты пунктов выдачи — ключ Яндекс.Карт (позже, это уже на витрине).

## Переменные окружения (Render → Environment, значения вводит владелец)
| Переменная | Значение |
|---|---|
| `CDEK_CLIENT_ID`, `CDEK_CLIENT_SECRET` | ключи интеграции |
| `CDEK_MODE` | `test` (по умолчанию) или `prod` |
| `CDEK_FROM_CITY_CODE` | код города отправления |
| `CDEK_SHIPMENT_POINT` | код пункта/склада сдачи |
| `CDEK_SENDER_NAME`, `CDEK_SENDER_PHONE` | отправитель |
| `CDEK_TARIFF_CODE` | необязательно, по умолчанию 136 |
| `CDEK_DEFAULT_WEIGHT_G` | необязательно, вес единицы товара по умолчанию, 200 г |
| `CDEK_WEBHOOK_SECRET` | любая длинная случайная строка для адреса вебхука |

Ключи только в переменных окружения на сервере. Во фронтенд и в репозиторий они не попадают.

## Порядок подключения, когда ключи придут
1. Добавить переменные для **теста**, дождаться сборки, в админке должны появиться кнопки.
2. Создать тестовую заявку, вписать код тестового пункта, подтвердить, нажать «Создать накладную».
3. Сверить ответ СДЭК с тем, что мы отправляем (раздел заказов в документации), поправить `server/routes/cdek.js`.
4. Зарегистрировать вебхук у СДЭК на `https://<адрес сайта>/api/cdek/webhook?token=<CDEK_WEBHOOK_SECRET>` (тип статусов заказа).
5. Переключить `CDEK_MODE=prod` и ввести боевые ключи.

## Что ещё впереди (не сделано)
- Выбор пункта выдачи на карте в форме заявки (виджет СДЭК + ключ Яндекс.Карт) и расчёт доставки покупателю.
- Коды маркировки «Честного знака» в накладной: добавляются только на сервере; нужна привязка кодов к товарам.
- Вес и габариты по каждому товару в админке (сейчас вес по умолчанию, поле в базе уже есть).
